# @cineforge/motion-canvas-template

Motion Canvas 3.17 starter template for CINEFORGE. Motion Canvas drives
**explainer-style 2D animation** - procedural, code-authored motion for
labeled diagrams, charts, step-by-step walkthroughs and kinetic schematics.
It complements the Remotion template (`../remotion-template/`), which handles
promo/typography compositions:

| Engine        | Role at CINEFORGE                                                      |
| ------------- | ---------------------------------------------------------------------- |
| Remotion      | Promo / hook / typography comps, storyboard-driven `CinematicPromo`     |
| Motion Canvas | Procedural explainers: charts, diagrams, annotated sequences            |

Both engines live under `packages/video-engine/` and both ultimately consume
the same director-agent artifacts (Storyboards in `docs/API_CONTRACTS.md`
format).

## What is inside

- `src/project.ts` - the Motion Canvas project (registers the explainer scene).
- `src/scenes/explainer.tsx` - a real title-card scene: dark backdrop,
  tracked-out "CINEFORGE" title (letter-spacing tween), growing accent rule,
  fading subtitle, and a polyline chart that draws itself in by tweening its
  points; ends with a short hold (`waitFor`).
- `src/motion-canvas.d.ts` - ambient type reference that types the
  `?scene` module imports (`@motion-canvas/core/project` declarations, same
  as the official Motion Canvas TS starter).
- `vite.config.ts` - wires `@motion-canvas/vite-plugin`, which auto-detects
  `src/project.ts` and generates `.meta` files next to scenes.

The project uses only stable v3 API: `createRef`, `view.add()`, and the
`yield* node.property(value, duration)` signal-tween pattern.

## Running

```bash
npm install

# Start the Motion Canvas editor (Vite dev server)
npm run serve

# Production build of the editor bundle
npm run build
```

`npm run serve` opens the Motion Canvas editor (by default at
http://localhost:5173): scrub the timeline, hot-reload scene code, and render
from the editor's export panel (MP4 / PNG sequence) to the `output/` folder.

Note for headless rendering: this template does not wire a CI render runner
yet. Until a dedicated CLI job exists, render through the editor export panel.
This is tracked as part of the M4 work below.
